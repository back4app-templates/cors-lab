Preflight-tax series

Three SEPARATE series (amendment B4), each with its own sample count and warm-up policy:

  • simple — GET /timing/simple, same URL; house rule: 20 warm-ups discarded, 100 timed.
  • preflight-cached — JSON POST /timing/preflight?maxage=600, same URL every sample so Access-Control-Max-Age caches the preflight after the first; 20 warm-ups (which deliberately warm the cache) discarded, 100 timed. The count of OPTIONS requests observed is read from the API's /__state counters before/after.
  • cold — ONE preflighted JSON POST per fresh browser context, no maxage, and no warm-ups: the house 20-warm-up rule is waived for this series because it would erase exactly the cost under study. Use ?series=cold&autorun=1: the capture driver launches a fresh context per sample and scrapes #result. Running cold samples by clicking inside one warm page does NOT produce the cold series.

No claim about the browser's maximum preflight-cache lifetime is made from these runs; only cache behaviour observed within the stated run window is reported.
